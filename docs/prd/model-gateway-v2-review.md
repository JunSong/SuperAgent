## 3. 本轮发现

### P1 · 进 G2 前必须改（不挡 G0）

| # | 问题 | 证据 | 影响 | 给 Codex 的修改指令 |
|---|---|---|---|---|
| **P1-1** | **G2 验收把「余额不足」写成了 `QUOTA_BUSY`** | §7 G2：员工可用 100，20 次并发各申请 R=60，期望「恰好 1 次出站，另 19 次均为 QUOTA_BUSY」。首笔预占 60 后剩余 40&lt;60，其余请求应按**额度不足**拒绝（`QUOTA_EXHAUSTED` 或单独的 `QUOTA_INSUFFICIENT`），不是「暂占满 B 时的等待队列忙」。§6 对 `QUOTA_BUSY` 的定义是并发暂占逼近 B 时的短等待 | G2 自动化会按错误语义写断言；实现者为凑「19 次 BUSY」会扭曲队列语义 | 拆成两个用例：**(A) 余额不足**：可用 100、并发 N×R=60 → 1 出站 + (N−1) 不足类错误、0 出站；**(B) 队列忙**：构造「已用接近 B、多个小 R 并发抢最后额度」→ 最多 2 个等待、超时 `QUOTA_BUSY`、可重试。栅栏延迟结算只用于证明「预占已提交后再出站」，不要和 BUSY 绑死 |
| **P1-2** | **工具往返「不另扣额度」易误读** | §3：「一次工具回传本身不另扣额度」；同节又写「同一 run 的多次模型请求各有自己的 attempt」 | 实现者可能漏掉 tool 之后的模型请求预占 | 改成：「工具结果报文本身不扣费；工具后的每一次模型补全仍是独立 attempt，须按 §4/§5 增量预占。」 |

### P2 · 实施中补齐

| # | 问题 | 建议 |
|---|---|---|
| **P2-1** | **公司准备金进了 §4，未进 §5 守恒式** | §4：「准备金从未分配池划拨，在守恒式中列为公司专用账户」。§5 公式仍是「未分配 + 上浮预留 + 员工/系统可用 + 在途 + 已结算」，缺「对账准备金/专用账户」。补进公式与 `gateway_account.type` 枚举 |
| **P2-2** | v0.1 归档只写在合并稿 §8「建议」 | 直接改 `docs/prd/model-gateway-tech-design.md` 文首加归档戳（可用稿内已写好的那句） |
| **P2-3** | G1 用 claude 仅桩测身份，与「warm 路径」目标之间的跨度大 | G0/G1 退出条件写清：G1 只验收令牌/隔离/流式泵送；**warm 换令牌保真**列为 G0 对 deepseek（或确有 warm 的 runner）的实测项，claude warm 若桩无法模拟则标 `[G0 对真实 CLI 授权后补]`，避免 G1 假通过 |
| **P2-4** | 请求体「完整读取 8 MiB」改变了纯透传假设 | 可接受；在 §4 注明：**请求**可有界缓冲计数，**响应**仍逐块泵送、不整包缓冲。与 v0.1「不缓冲响应」对齐，避免实现者连响应一起 buffer |
| **P2-5** | 对账准备金 2 个工作日转公司户 | 产品/财务待确认（稿末已有待决）；补一句「未演练通过不对真实员工启用」已有——保持，并列入 G3 前检查单 |

### 非问题（确认写对了）

- hop/failover **增量预占、不重算整轮、撤销旧令牌**——与 `ChatService` MODEL_HOPS / failover 匹配。
- 「继续」= 新 turn 重新准入——避免旧窗偷渡上浮。
- managed 故障不得切回 legacy 直连真 Key——与合并稿评审 P1-E 一致。
- `QUOTA_BUSY` → HTTP 409 / `BusyException` 语义——方向正确（修 P1-1 后更干净）。
